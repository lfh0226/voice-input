# 架构决策记录(ADR)

## D1 选择 fcitx5 输入法插件,而非 IBus(2026-10-01)
Ubuntu 26.04/GNOME 50 已移除 Xorg 会话;IBus 引擎在 GNOME 下无法获得焦点握手(实测),
且 libpinyin 引擎自身启动超时。fcitx5 是用户现有输入栈,其 IM 插件 commit 通道经过验证。
**代价**:需开发 C++ 插件。**状态**:已采纳。

## D2 IPC 采用 Unix socket + 行分隔 JSON(2026-10-02)
插件必须在 fcitx5 进程内才能 commit;daemon 与插件跨进程通信选最简可靠的本地流。
注意 fcitx5 事件循环为边缘触发语义 → 必须 ready 握手防止首条消息丢失。
**遗留**:V3 改进为长度前缀协议并引入正式 JSON 库。**状态**:已采纳。

## D3 切换 IM 后注入 Shift 敲击强制 IC 重挂载(2026-10-02)
实测 `fcitx5-remote -s voice` 切换后,应用侧 IC focusOut 不自动恢复,final 时
focusedIC 为 null 导致 commit 丢失(时好时坏根因)。ydotool 注入 Shift 敲击可强制
IC 重新挂载。**已知局限**:按键注入属 hack,依赖 ydotoold;V2 探索免注入方案。**状态**:已采纳。

## D4 首个 ASR 后端选讯飞流式(2026-10-01)
用户已有 API 配额;支持流式中间结果与 dwa=wpgs 语境动态纠错。延迟上限由服务端
出字节奏决定(约 0.3~1s/批)。V2 起后端可插拔,可切换本地模型(funasr)以突破延迟。
**状态**:已采纳。

## D5 Python daemon + C++ 插件分工(2026-10-02)
C++ 只承担必须在 fcitx5 进程内的最小职责(渲染+提交);Python 承载全部业务逻辑
(热键/录音/ASR/纠错/回退)。迭代集中在 Python,插件协议稳定后不动。
**状态**:已采纳,见 ARCHITECTURE.md。

## D6 长语音分段自动上屏(2026-10-02)
每累计 ≥10 新字且距上次提交 ≥2 秒,把已识别前缀直接 commit;final 只提交剩余增量。
代价:已上屏前缀不再参与后续纠错修正。用户明确接受该取舍。
**状态**:已采纳。

## D7 许可证 MIT、分支模型 GitFlow-lite(2026-10-02)
MIT 与 fcitx5 生态一致,最大化采用率;分支模型见 BRANCHING.md。**状态**:已采纳。

## D8 V2.1 常驻监听先用能量 VAD,默认关闭(2026-10-02)
为消除首句 WS 建连延迟,本地能量 VAD 分段并让 ASR 会话后台接力;确认前音频
从 prebuffer 回放,不丢首字。第一阶段不引入模型级 VAD 依赖,且常驻麦克风
涉及隐私,策略必须真机校准后再通过 `resident.enabled` 显式开启。**状态**:已采纳。
